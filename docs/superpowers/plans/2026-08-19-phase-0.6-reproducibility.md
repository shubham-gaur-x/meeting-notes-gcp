# Phase 0.6 Reproducibility Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a fresh clone diagnosable and self-explaining — `make doctor` tells you exactly what is missing for whichever tier you are targeting, and `docs/SETUP.md` tells you how to fix it.

**Architecture:** `scripts/doctor.py` is a tier-aware preflight. Every check is a pure function returning a `CheckResult`, with its environment probe injected as a parameter so the whole suite runs with no Docker, no network, and no `gcloud`. Tier 0 (local) checks stand alone; tier 1 (LLM) and tier 2 (cloud) are additive. Supporting scaffolding — local compose, expanded `.env.example`, example tfvars, `SETUP.md` — ships alongside it.

**Tech Stack:** Python 3.11+ · `structlog` · stdlib `socket`, `shutil`, `subprocess` · `pytest`

## Global Constraints

Copied verbatim from `CLAUDE.md` and the approved spec (`docs/superpowers/specs/2026-08-13-clone-and-run-design.md`).

- Type hints on **all** function signatures.
- Structured logging with `structlog`. **Never pass `event=` as a kwarg** — collides with structlog's reserved field, raises `TypeError` at call time.
- **Credentials are reported as `set` / `unset` / `expired`. No value is ever printed, in whole or in part. No prefix, no length, no truncation.** (`GOOGLE_AUTH.md` §7)
- Tests are mocked — the suite must run with no live GCP, no database, no LLM. A test requiring live credentials is a broken test.
- **Every `FAIL` carries a remediation** — a runnable command or a document anchor.
- Exit codes: `0` all pass · `1` at least one FAIL · `2` warnings only.
- Do not read `os.environ` outside `config.py` — `doctor.py` is a Phase 0.6 script predating `config.py`, same documented exception as `auth_spike.py`; it takes `env` as a parameter rather than reaching for the global.

## Scope note

This plan builds **only** §4.1 of the spec. The `fake`/`gemini` LLM backends (§7), sample corpus (§8), dual-mode `db.py` (§9), and a real `make demo` (§3) are deferred to Phases 3/4/6 by the spec and are **not** built here. `make demo` is deliberately left as a target that explains it is not ready yet rather than a broken command.

### Task 2: `CheckResult`, `Status`, and report rendering

Start with the value type and the renderer, since every later check produces one and the no-secrets guarantee is asserted here.

**Files:**

- Test: `tests/test_phase06_doctor.py`

**Interfaces:**
- Produces: `Status` (str enum: `PASS`, `WARN`, `FAIL`), `CheckResult` (frozen dataclass: `name: str`, `status: Status`, `detail: str`, `remediation: str | None = None`), `render_report(results: list[CheckResult], tier: int) -> str`, `exit_code_for(results: list[CheckResult]) -> int`

- [ ] **Step 1: Write the failing tests**

```python
from scripts.doctor import CheckResult, Status, exit_code_for, render_report


def test_exit_code_zero_when_all_pass() -> None:
    assert exit_code_for([CheckResult("a", Status.PASS, "ok")]) == 0


def test_exit_code_one_on_any_fail() -> None:
    results = [
        CheckResult("a", Status.PASS, "ok"),
        CheckResult("b", Status.FAIL, "bad", "run something"),
    ]
    assert exit_code_for(results) == 1


def test_exit_code_two_on_warnings_only() -> None:
    results = [CheckResult("a", Status.PASS, "ok"), CheckResult("b", Status.WARN, "meh")]
    assert exit_code_for(results) == 2


def test_report_shows_every_remediation_for_failures() -> None:
    report = render_report(
        [CheckResult("terraform", Status.FAIL, "not installed", "brew install terraform")], tier=2
    )
    assert "FAIL" in report
    assert "terraform" in report
    assert "brew install terraform" in report


def test_report_states_which_tier_was_checked() -> None:
    assert "tier 0" in render_report([], tier=0).lower()
```
